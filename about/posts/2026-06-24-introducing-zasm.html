Introducing zasm — ZIR Assembler

2026-06-24

zasm is a standalone assembler for ZIR, the Zith Intermediate Representation. It takes .zas files, assembles them to ZIR bytecode and runs them through a built-in interpreter. Since ZIR is the same IR zithc targets, that gives a direct path from assembly to execution without dragging the whole compiler along.

It is still WIP, but small programs work today.

What's in it

  • Arithmetic and floats — add, sub, mul, div, rem for integers, fadd/fsub/fmul/fdiv plus fld/fst for floats, and conversions in both directions (ftoi, itof)
  • Control flow and calls — br and the conditional branches (bz, bnz, bgt, ble), call with working recursion, and callext for external C functions
  • Memory — load/store, push/pop, alloca, and stm for storing multiple registers at once
  • Directives — .const for integers, floats, strings and typed data, .extern for external C declarations, and #define for textual macros
  • Names — labels scoped to the enclosing function inside { } blocks, and forward references for both branches and calls

Some examples. Arithmetic:

main:
    li      a0, 10
    li      a1, 32
    add     a0, a0, a1        ; a0 = 42
    add     ret, a0, zero
    ret

Recursive factorial — note the scoped block, which keeps base_case from leaking:

main:
    li      a0, 5
    call    fact, 1
    ret

fact:
{
    push    a0
    li      t0, 1
    sub     t0, a0, t0
    ble     t0, base_case
    li      t0, 1
    sub     a0, a0, t0
    call    fact, 1
    pop     a0
    mul     ret, a0, ret
    ret
}

base_case:
    li      ret, 1
    pop     t0
    ret

And calling libc's write through FFI, where the argument block is built by hand:

.const msg .asciz "hello from write\n"

main: (i32, *char, i64) > i64 {
    alloca a0, 48
    li t0, 3
    st t0, a0, 0            ; nargs = 3
    li t0, 1
    lea t1, db, msg
    li t2, 18
    stm a0, 8, t0, t1, t2   ; fd, buf, count
    callext write
    ret
}

Why it exists

Because zasm and zithc reach the same bytecode format, a program can mix them — hot paths written directly in zasm, the rest in Zith. It also gives me a way to poke at ZIR without going through the frontend, which is worth a lot when the frontend is the thing I am debugging.

It lives in the main repo under lib/zasm/. Build with cmake -B build && cmake --build build; more examples are in lib/zasm/examples/.

What's next

The syntax is noisier than it needs to be, especially around FFI argument setup, and I want to cut the boilerplate. The namespace rules for labels versus functions are correct but their error messages are not. ZIR emission is done; lowering ZIR to LLVM IR is the next real piece.
