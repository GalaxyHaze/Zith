Operators, and Where Ownership Belongs

2026-08-06

Two unrelated-looking pieces of work this week: finishing the operator surface, and deciding where in the pipeline ownership proof runs. They are connected by the same lesson — a thing that looks like a small local decision is usually a contract.

The lexer bug I should have caught earlier

The lexer munches multi-character operators longest-first. Every operator except one. The range operator .. lexed per character and carried a precedence of -1, and && had inherited the same treatment: it lexed as two & tokens, and with precedence -1 the parser stopped after the left operand.

So if (a && b) compiled. It did not error. It compiled to if (a) and silently threw away b. That is the worst class of bug I have shipped in this compiler — not a crash, not a rejection, just a program that means something other than what it says.

&& and || are now lexed as single tokens for the sole purpose of rejecting them, with a dedicated message pointing at and and or, exactly one diagnostic and no cascade. Zith uses keywords for logical operators, so the symbols were never going to mean anything; they just needed to say so out loud.

Bitwise, and the dot

With the keywords owning and / or / xor, the bitwise operators keep a trailing dot: &., |., ^., plus unary ~. Both operands must be integers of the same width. They share the underlying HIR ops with the keyword forms, which is fine — the distinction is in the type rules, not the lowering. 

fn bits(a: i32, b: i32): i32 {
    let both: i32 = a &. b;
    let either: i32 = a |. b;
    ~(both + either)
}

Compound assignment costs nothing

+= and its nine siblings are pure parser desugaring: a += b becomes Assign(Binary(a, b)) before sema ever sees it. No new expression kind, no new HIR node, no new case in codegen. The payoff is that compound assignment automatically inherits everything = already does — coercion rules, yielding a value, and the view write check. If I had given it its own node I would have had to remember to re-implement each of those, and I would have forgotten one.

raw opaque landed alongside it. It is a real type now rather than an alias for *void (which is rejected outright), and it casts to and from any *T with as. That is what you need to hold a pointer whose pointee you do not want to name, and it keeps the honest untyped case visibly distinct from a typed pointer.

Where ownership belongs

Now the part that took the actual thinking. NRA — the ownership analysis the memory model is built on — needs to prove things about resources: what is alive, what has moved, what is merely lent. All of that is information the frontend knows and lowering throws away. HIR is deliberately small; it does not have qualifiers, it does not distinguish a lend from a value, and that is the right design for a lowering IR.

Which means the proof cannot run after lowering. If you erase the facts and then try to reconstruct them from the IR, you are writing a worse analysis on worse input, and you will be wrong in exactly the cases that matter. The order has to be sema -> comptime/solve -> NTA/NRA -> HIR, with ownership proved on a representation that still knows what a resource is.

So that boundary is what I built, before building the analysis itself. Semantic facts are accumulated during sema and consumed before final lowering, and residual facts attach to side tables rather than adding ownership nodes to HIR. The IR stays clean; the analysis gets its inputs. Getting this right first is the difference between an ownership pass and an ownership pass I have to rewrite.

The qualifiers themselves — mut, lend, view, unique, share, belong — now parse anywhere a type is written and are carried in the type table. One rule is enforced end to end: 

fn bad(x: view i32): i32 {
    x = 5;
    x
}

That reports E4004: a view binding is read-only, take lend to mutate it. One rule out of a state machine's worth is not much, but it is the first ownership error the compiler has ever emitted, and it comes out of the real mechanism rather than a special case.

What NRA still owes

The alive/dead/lent state machine is unwritten. E4001 use-after-move, E4002 borrow conflict, and E4003 double borrow have codes and no implementation behind them. Some paths still lower before the full proof runs, which is the remaining half of the boundary work. I am keeping all of that visible in docs/impl-status.md rather than letting the spec imply it works.
