Formatting, a C ABI, and Three Operating Systems

2026-06-21

A lot has landed in zithc since the last update, in three areas that have nothing to do with each other except that all three were blocking something.

The formatter is a real pass now

Formatting used to be an afterthought bolted onto the side of the compiler. It is now a proper pass: a dedicated FmtVisitor walks every declaration, statement and expression kind, with precedence-aware output and real brace-block handling.

Run it with zith fmt on any source file. It handles comma-separated lists, complex type expressions, semicolons versus braces, and nested blocks without special-casing them. The companion test suite in tests/unit/fmt-visitor.cpp is what keeps output stable across refactors — formatting regressions are silent otherwise.

The C API grew up

The C ABI that the LSP consumes got the bulk of the work. Session lifecycle is solid — create from a file or a buffer, run the pipeline, destroy — and four things are new on top of it:

  • zithc_hover() — resolves the identifier at a byte offset and returns a markdown signature
  • zithc_offset_to_position() — byte offsets to 0-based line/column pairs
  • Diagnostics with suggestions — the "did you mean?" engine and overload error enrichment, exposed to tooling
  • merge_sym() — preserves declaration IDs, spans, kinds and targets across imports, which is the groundwork for go-to-definition

The boundary is also cleaner than it was: I ripped out every try/catch in favour of nothrow new. A C boundary should be pure C, with no exception machinery waiting to unwind through it.

Three platforms, one build

CI now covers Linux, Windows (MSVC and clang-cl) and macOS (x86_64 and ARM64). Getting there was a list of small indignities:

  • unistd.h guarded behind _WIN32, and isatty fixed on Windows
  • xcrun for SDK path discovery on macOS
  • Zig cc for Windows ARM64, which cross-compiles reliably where the alternatives did not
  • A Token constructor fixed for musl libc
  • The OBJECT library pattern removed, because it broke macOS universal binaries

The formatter and the CLI now share common file and terminal utilities, so the next command does not reinvent the same wheels a third time.

v0.3.1 shipped the critical bug fixes — a dangling TypeFn span, undefined behaviour on an empty token stream, a lexer null fallthrough, a TOCTOU race in SourceMap — but the real headway this week is the CAPI and the formatter.
