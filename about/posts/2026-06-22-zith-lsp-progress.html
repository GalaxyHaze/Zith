Zith Language Server Progress

2026-06-22

zith-lsp is finally doing something. The binary itself is thin — almost all the intelligence lives in the CAPI layer I wrote up yesterday, and the server is a wrapper that speaks LSP on one side and the C ABI on the other. That split was deliberate and it is paying off: every capability below came from work already done in the compiler.

What works

Hover. Point at an identifier and the editor shows its type, rendered as a markdown function signature, without re-parsing the file.

Diagnostics that guess. The heuristic engine is on the LSP path now. An undefined identifier does not just get reported — the closest match by Levenshtein distance comes with it. For ambiguous calls and no-matching-function errors you get every candidate signature listed, which is usually enough to see what went wrong without opening the definition.

Cross-file symbols. Declaration IDs, spans, kinds, targets and documentation spans now survive an import boundary. Nothing user-visible depends on that yet; it is the data foundation that go-to-definition and find-references will sit on.

Build

The LSP builds alongside the compiler in CI. macOS produces a universal binary, Windows works under both MSVC and clang-cl, and the CI caches have been cleaned out to stop the corruption we kept hitting.

Next

Completions and go-to-definition. The symbol table and the cross-file merging are ready — what is left is wiring the protocol messages, which is the least interesting half and the half that makes it real.
