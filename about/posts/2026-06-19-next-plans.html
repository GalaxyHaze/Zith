What Comes Next

2026-06-19

A roadmap is mostly a way of admitting what is not done yet, so here is mine, grouped by how far away it feels rather than by when I promise to ship it.

Short-term (v0.4.0)

The type system needs the TypeWalker wired into every pass that still duplicates the type-kind switch. Unification was the first consumer and it proved the shape works; the rest are copy-paste waiting to drift apart.

CompilationSession is the other structural item. The pipeline has more stages than it did when I wrote it, and stage isolation and error recovery are both weaker than the number of stages now justifies. After that, the diagnostic engine needs "did you mean?" coverage for type mismatches and missing symbols, not just identifiers, and the standard library needs Array, List and Map to be usable from Zith code rather than existing on paper.

Medium-term

A Zith parser written in Zith is the milestone I want most, and it is gated on FFI and bootstrapping being solid first — writing it earlier just means writing it twice. The MIR needs a real optimization pass pipeline before any of the generated code is worth measuring.

The package manager works in the sense that zithc new and zithc build do what they say and dependency resolution resolves dependencies. The UX around all of it is rough enough that I would not hand it to anyone yet.

Long-term

The LLVM backend exists and emits IR; codegen quality and platform coverage are where the work is. The language server has foundations but is disabled — proper IDE support is the single thing most likely to make the language usable by someone other than me.

And then self-hosting, which is the point where the language stops being a project about a compiler and starts being a language.

This is a solo project, so it moves at the pace a solo project moves. The order above is more reliable than any date I could put next to it.

— Haze
