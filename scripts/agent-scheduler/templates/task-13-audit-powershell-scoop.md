# {AGENT}: {TASK}

## Goal

Audit `scripts/install.ps1` and the Scoop manifest
`.github/scoop/bucket/zithc.json`, align both with the current release
repository/asset names, and ensure installed binaries can locate the standard
library.

## Context

- Plan: Windows installer/Scoop audit.
- Worktree: {REPO}/.awt/{AGENT} (branch awt/{AGENT}).
- The compiler main targets `Zith--`, a sibling language to Zith. Zith-specific
  compiler artifacts are out of scope.
- `scripts/install.ps1` downloads and installs to
  `%LOCALAPPDATA%\Microsoft\WindowsApps`.
- The Scoop manifest pins version `0.6.2`, uses the old `Zith-Lang` owner, and
  does not carry a checkver/autoupdate section.
- Release assets are created by `.github/workflows/build-artifact.yml` from the
  `${{ github.repository }}` repository (currently `GalaxyHaze/Zith`).

## Scope

1. Read `scripts/install.ps1`, `.github/scoop/bucket/zithc.json`,
   `.github/workflows/update-package.yml`, and
   `.github/workflows/build-artifact.yml`.
2. Document differences between the PowerShell installer and the Scoop
   manifest: repo owner, version, asset names, stdlib archive, install layout.
3. Fix issues that are obviously stale or incorrect for the current release:
   wrong repository/URL/hash/version drift, missing `checkver`/`autoupdate`
   metadata if appropriate for this repo's workflow, and stdlib extraction
   paths that do not match `findStdlibRoots()`.
4. Keep PowerShell 5.1-compatible syntax; Scoop changes must remain valid JSON
   with at least the existing architecture fields.
5. Do not invent release hashes. If hashes cannot be verified locally, mark
   them as placeholders/blockers in the task body and file a debt note instead
   of guessing.

Out of scope:

- Publishing a real Scoop bucket or Homebrew tap.
- Changing the release workflow.
- Editing non-Windows installers.

## Acceptance Criteria

- `scripts/install.ps1` uses the same repository/version/asset conventions as
   the release workflow, or documents the mismatch that prevents that.
- The Scoop manifest points at the correct repository owner for new versions,
   or the task records exactly what must be regenerated by the package
   workflow.
- Stdlib extraction produces a directory that `findStdlibRoots()` will find on
   Windows.
- No fake hashes are introduced.
