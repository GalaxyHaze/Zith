# Step 5 --- AST Builder Helpers

## Summary

Add template-based AST manipulation headers in `common/ast/` that work with
any AST satisfying an `AstNode` concept: clone, replace, prune, visit, and
transform. These are pure headers with zero dependency on `generated_ast`.

Depends on Steps 1 and 2.

## Design

All helpers are C++20 templates. An AST node type `T` supports these
helpers if the user (or a future AST generator) provides a free function
`for_each_child(T *node, Fn&& fn)` in the same namespace as `T`.

A `ChildVisitor` concept captures this:

```cpp
template <typename T, typename Fn>
concept HasChildVisitor = requires(T *node, Fn fn) {
    for_each_child(node, fn);
};
```

For types generated by `ast.rules`, the user either writes the
`for_each_child` overloads manually or we extend the AST generator in
a future step to emit them. For hand-rolled ASTs (the common case for
this branch), the user writes them in their `types.hpp` or a companion
header.

## API

### `common/ast/clone.hpp`

```cpp
namespace common::ast {

// Deep-clone a node tree into the target AstRoot.
// `AstRoot` must support `arena->make<T>(Args&&...)`.
template <typename T, typename AstRoot>
T *cloneNode(AstRoot &target, T *source);

// Clone the full tree rooted at `sourceRoot`.
template <typename T, typename AstRoot>
T *cloneTree(AstRoot &target, T *sourceRoot);

} // namespace common::ast
```

`cloneNode` recursively clones children. The target `AstRoot` owns the
allocated memory.

### `common/ast/replace.hpp`

```cpp
namespace common::ast {

// Replace `oldNode` with `newNode` in `parent`. Returns true if replaced.
// parent must be the direct parent of oldNode.
template <typename T>
bool replaceChild(T *parent, T *oldNode, T *newNode);

} // namespace common::ast
```

### `common/ast/prune.hpp`

```cpp
namespace common::ast {

// Remove `child` from `parent`. Returns true if removed.
// The node is not deallocated; caller manages lifetime.
template <typename T>
bool pruneChild(T *parent, T *child);

} // namespace common::ast
```

### `common/ast/transform.hpp`

```cpp
namespace common::ast {

// Post-order walk. Calls fn(node, parent) at each node.
// If fn returns a non-null T*, the node is replaced in the parent.
// If fn returns nullptr, the node is kept.
// parent is nullptr for the root.
template <typename T, typename Fn>
void transform(AstRoot &ast, T *root, Fn &&fn);

} // namespace common::ast
```

`transform` allocates new nodes via `ast.arena->make<T>(...)` and is
designed to work with `AstRoot` from `generated_ast` or any compatible
root type.

### `common/ast/visit.hpp`

```cpp
namespace common::ast {

// Pre-order walk with parent tracking. fn(node, parent) is called at each node.
// parent is nullptr for the root.
template <typename T, typename Fn>
void visit(T *root, Fn &&fn);

} // namespace common::ast
```

This is a generalized version of `generated_ast::walk` that does not
require an `AstRoot` object; it walks from a raw pointer using
`for_each_child`.

### `common/ast/concepts.hpp`

```cpp
namespace common::ast {

template <typename T, typename Fn>
concept HasChildVisitor = requires(T *node, Fn fn) {
    for_each_child(node, fn);
};

} // namespace common::ast
```

## Implementation Changes

- Create `src/common/ast/` directory with:
  `concepts.hpp`, `visit.hpp`, `clone.hpp`, `replace.hpp`,
  `prune.hpp`, `transform.hpp`.
- Each header is self-contained; includes only `common/` deps
  (`arena.hpp`, `dyn-array.hpp`, `span.hpp`).
- `src/common/CMakeLists.txt`: add `${CMAKE_CURRENT_SOURCE_DIR}/ast/`
  to `target_include_directories` for `zith_common`.
  No `.cpp` files needed (all templates).
- `src/common/README.md`: add documentation section for AST helpers.

## Assumptions

- `for_each_child(T*, Fn&&)` is the contract between AST types and these
  helpers. The AST generator does not yet emit these; users define them
  manually. Emitting them from `ast.rules` is a future step.
- Memory management uses the arena/AstRoot pattern already established.
  `cloneTree`/`transform` allocate in the target arena.
- `pruneChild` does not deallocate; caller manages lifetime.
- These helpers do not depend on `generated_ast` and work with any AST
  type that satisfies the concept.
